# Session 3 GoldTier XPI field matrix

Prepared: 2026-10-04 (Asia/Singapore). Status: pre-execution inventory; no external acceptance result is asserted.

This matrix precedes all external execution for the owner-authorized fresh synthetic
onboarding package. The prepared-case receipt must bind the actual synthetic identity,
canonical values, case classifications, current policy/evidence versions, exact request
preview and review digest before mutation. It must supply safe dynamic IDs and values as
they become available; it must never expose user_id, endpoint secrets, raw provider
bodies, original document bodies, or real/private customer data. Configuration rows are
presence-only verification pending, not claims that this runtime is configured.

Requiredness distinguishes the current strict DTO from provider authority. Required
locally means construction/dispatch rejects absence. Guide minimum identifies an
explicit upstream minimum. Collection-only fields remain optional or unknown upstream;
example presence is not a business requirement. A container requirement is separately
listed from its leaves. Null, omitted, empty string, and pending are distinct: no value
is fabricated merely to remove null. All tables use the same 13 requested columns.

Canonical evidence can include validated registry facts and authorized reconciled
document observations. CANONICAL_EVIDENCE does not imply every value came exclusively
from the registry. Source provenance remains in the existing case/evidence owners. The
current four company extraction keys and separate proposed ownership observations do
not provide a contact, group-company, industry, address-type, or integration-constant
source. Provider IDs are never extracted from synthetic documents.

D-056 fixes only the bounded parent Singapore POC values: ACRA registration type,
DSD external system, Singapore policy and ANZBGL (Singapore Branch) booking entity.
D-057 requires explicit per-case KYC Customer Type and Client Segment selections from
the corrected OpenAPI 1.0.0 vocabularies; neither has a global default. Account/product
empty strings follow the bounded collection compatibility exception, not an invented
nonempty vocabulary. These choices do not establish production or Live authority.

The current Shell preview includes populated street2, matching the transmitted DTO.
The preview and dispatch remain bound to the same immutable canonical/policy input.
Preview placeholders for an ID to be returned by Search/Shell are explanatory and
must never be dispatched as provider-issued IDs.

- Current supported parent path: bounded documented Search, eligible customer
  create/reuse through the identity owner, Policy where required, optional supported
  Amend, and bounded exact-ID readback through the one target ledger. No name-only
  candidate becomes an exact reusable identity.
- D-063 permits AMEND_NOT_REQUIRED when no supported reviewed enrichment exists.
  The current builder emits no ANZSIC/group-company enrichment. Historical uncertain
  or failed Amend records remain truthful and are never replayed by this package.
- RP DTOs are locally represented, but provider child creation/retrieval/binding and
  relationship-value authority remain unproved. No fake child IDs, inferred boolean
  flags, or automatic economic-ownership-to-legal-control mapping are permitted.
  RP absence blocks parent submission only if an actual provider contract requires RP.
- Current response decoding retains provider-issued customer/optional Policy IDs.
  SHELL_CREATED, POLICY_CREATED, ENRICHED and VERIFIED are application-normalized
  technical facts, not raw provider statuses or regulatory approval. Readback requires
  one exact same-ID candidate and compares every returned projected business identity
  field; missing optional fields remain missing. It cannot prove Policy internals,
  completed KYC, screening clearance, risk approval or Ready-for-Approval.
- The six current XPI endpoints expose no original-file upload capability. A confirmed
  parent request can establish submission of supported fields extracted/reconciled
  from documents. It cannot establish transfer of the original file to GoldTier.
- Unexpected/uncertain mutation outcomes retain the attempted operation and stop.
  Only bounded read-only recovery is permitted; no automatic duplicate POST, provider
  retry or Sandbox-to-Mock fallback follows from this inventory.
