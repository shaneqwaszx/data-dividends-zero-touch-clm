## Zero-Touch Decision Model

| Class | Condition | Behavior |
| --- | --- | --- |
| Automated | Current evidence is complete, reliable and consistent under an existing rule | Complete the bounded stage and progress without an operator event |
| WARNING | Existing non-blocking metadata | Continue; expose the advisory meaning |
| RECOVERABLE_INPUT | Required document, ownership, identity or classification input is missing | Offer the exact input owner; validate and recompute after persistence |
| HUMAN_DECISION | A current discrepancy or safely resolvable ambiguity requires judgment | Expose only backend-authorized decisions with current evidence/version bindings |
| WAITING_EXTERNAL | Existing external dependency cannot currently resolve | Preserve the wait and backend-authored recovery instructions |
| HARD_SAFETY_STOP | Unsafe mutation uncertainty or unsupported unsafe continuation | Stop dependent dispatch; no blind retry, candidate selection or replay |

These are API projection classes derived from existing decision metadata. Durable
schema v7 and its enums are unchanged. The final Review & Send confirmation remains a
separate submission control and is not counted as an exception intervention.

Every intervention projection includes code, stage, class, reason, required inputs,
dependencies, authorized actions, backend mutation owner, resolution condition and
resume target. When no safe action exists, the backend supplies `no_action_reason`.

existing Review & Send surface.
