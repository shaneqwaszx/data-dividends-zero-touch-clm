# Pre-PR Checklist

Use this checklist in lifecycle Stage 4 (publication), after Stage 2 integrated
acceptance, exact independent Stage 3 `PASS`, and the authorized publication commit.
Record command output; do not mark an item complete from memory.

## Baseline and branch

- [ ] `FEATURE_BRANCH` is not `main`.
- [ ] Initial `BASE_SHA` is recorded.
- [ ] `git fetch origin` was run immediately before the drift check.
- [ ] Latest `origin/main` SHA is recorded.
- [ ] `git log --oneline HEAD..origin/main` is empty.
- [ ] If main advanced, `origin/main` was merged into the feature branch and the merge is
      recorded. A shared branch was not rebased.

## Conflict and delta audit

- [ ] Current implementation/instruction content matches the frozen path/diff/tree
      identity accepted by the independent reviewer; later report-only changes are
      separately identified.
- [ ] All intended/supporting feature work and reviewed integration resolutions are
      committed.
- [ ] `git status --short` is empty: no staged, unstaged, or untracked files remain.
- [ ] `git diff --name-only --diff-filter=U` is empty.
- [ ] No conflict marker remains in a changed text/source file or staged content.
- [ ] `git diff --check` passes.
- [ ] Before task-owned new files were staged, their whitespace was checked explicitly;
      plain `git diff --check` was not treated as coverage for untracked Markdown.
- [ ] Every file in `git status --short` and
      `git diff --name-status origin/main...HEAD` is classified:
  - `INTENDED`: directly implements the task.
  - `SUPPORTING`: required test, documentation, fixture, or tooling.
  - `UNEXPECTED`: safely remove it only if this task owns it; otherwise preserve it and
    stop for owner guidance.
- [ ] Hotspot changes are deliberate and minimal.
- [ ] Dependency/lockfile changes correspond to an intentional dependency change and
      were generated by the repository package manager.
- [ ] Existing CI jobs/checks remain present.

## Contracts and behavior

- [ ] API routes/models, shared types, persistence schema, connector interfaces,
      configuration names, business rules, mappings, and security/auth behavior were
      either unchanged or explicitly disclosed in the task report and PR.
- [ ] Current main behavior was preserved unless an assigned requirement superseded it.
- [ ] No removed API, UI behavior, security default, mock, configuration, or stale phase
      claim was resurrected.

## Verification

- [ ] Stage 2 evidence covers the complete applicable change-class set (backend,
      frontend, type/lint, contract, security, dependency-integrity, build, and any
      browser/physical/OCR/lifecycle checks) and passed on a recorded content identity,
      integrated `origin/main` SHA, and environment.
- [ ] That identity matches the reviewed content, or every result invalidated by a later
      change or drift merge was rerun; unchanged valid evidence was reused, not repeated.
- [ ] `python scripts/pre_pr_check.py` returns PASS.
- [ ] Skipped or unavailable checks are named; the branch is not called merge-safe while
      a required check lacks evidence.

## Handoff

- [ ] PR template includes branch/SHA evidence, changed areas, hotspots, integrated
      acceptance evidence and identity, independent QG verdict and reviewed identity,
      checker result, conflict resolutions, assumptions, limitations, and reviewer
      attention.
- [ ] Every claim is labeled accurately as observed, inferred, or assumed where the
      distinction matters.
- [ ] PR targets `main`; final integration is a repository-owner squash merge.

## Publication and remote evidence

- [ ] Publication was explicitly authorized after exact independent `PASS`; `PASS WITH
      MINOR FIXES` did not qualify without remediation and recheck. The publisher did not
      alter reviewed content or bypass a platform approval prompt.
- [ ] Only reviewed task-owned paths plus the assigned independent report were staged,
      and the staged diff/whitespace was inspected before commit.
- [ ] Any latest-main integration that changed reviewed content received a fresh
      independent recheck before publication continued.
- [ ] Local and remote feature-branch SHAs match after push.
- [ ] Remote evidence records repository/PR, head/base, workflow event, actual checkout
      SHA/tree when available, run/attempt, and relevant job conclusions.
- [ ] Applicable push and `pull_request` runs are assessed separately; a PR-only query is
      not used as push evidence and no failing applicable run is dismissed because a
      different run passed.
- [ ] Pending CI is reported as `CI IN PROGRESS`; failures identify the actual check and
      evidence; skipped or cancelled jobs are not counted as passed. No unattended
      monitoring is promised.
- [ ] `HOSTED_CI_NOT_EXECUTED — BILLING/INFRASTRUCTURE BLOCKED` is used only with
      GitHub run/job/annotation evidence; the local evidence is recorded, any manual-CI
      exception is left to the owner, and blocked CI is never reported as passed.
