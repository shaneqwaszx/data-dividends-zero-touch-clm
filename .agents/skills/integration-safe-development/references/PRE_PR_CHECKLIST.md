# Pre-PR Checklist

Use this checklist only after implementation and latest-main integration. Record command
output; do not mark an item complete from memory.

## Baseline and branch

- [ ] `FEATURE_BRANCH` is not `main`.
- [ ] Initial `BASE_SHA` is recorded.
- [ ] `git fetch origin` was run immediately before the drift check.
- [ ] Latest `origin/main` SHA is recorded.
- [ ] `git log --oneline HEAD..origin/main` is empty.
- [ ] If main advanced, `origin/main` was merged into the feature branch and the merge is
      recorded. A shared branch was not rebased.

## Conflict and delta audit

- [ ] All intended/supporting feature work and reviewed integration resolutions are
      committed.
- [ ] `git status --short` is empty: no staged, unstaged, or untracked files remain.
- [ ] `git diff --name-only --diff-filter=U` is empty.
- [ ] No conflict marker remains in a changed text/source file or staged content.
- [ ] `git diff --check` passes.
- [ ] Every file in `git status --short` and
      `git diff --name-status origin/main...HEAD` is classified:
  - `INTENDED`: directly implements the task.
  - `SUPPORTING`: required test, documentation, fixture, or tooling.
  - `UNEXPECTED`: safely remove it only if this task owns it; otherwise preserve it and
    stop for owner guidance.
- [ ] Hotspot changes are deliberate and minimal.
- [ ] Dependency/lockfile changes correspond to an intentional dependency change and
      were generated by the repository package manager.
- [ ] Existing CI jobs/checks remain present.

## Contracts and behavior

- [ ] API routes/models, shared types, persistence schema, connector interfaces,
      configuration names, business rules, mappings, and security/auth behavior were
      either unchanged or explicitly disclosed in the task report and PR.
- [ ] Current main behavior was preserved unless an assigned requirement superseded it.
- [ ] No removed API, UI behavior, security default, mock, configuration, or stale phase
      claim was resurrected.

## Verification

- [ ] Focused tests pass.
- [ ] Applicable repository-defined backend, frontend, type/lint, contract, security,
      dependency-integrity, and build checks pass.
- [ ] `python scripts/pre_pr_check.py` returns PASS.
- [ ] Skipped or unavailable checks are named; the branch is not called merge-safe while
      a required check lacks evidence.

## Handoff

- [ ] PR template includes branch/SHA evidence, changed areas, hotspots, tests, checker
      result, conflict resolutions, assumptions, limitations, and reviewer attention.
- [ ] Every claim is labeled accurately as observed, inferred, or assumed where the
      distinction matters.
- [ ] PR targets `main`; final integration is a repository-owner squash merge.
